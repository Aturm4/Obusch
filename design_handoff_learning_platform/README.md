# Handoff: Платформа для обучения дизайну (UI/UX Design — закрытый клуб)

## Overview
Премиальная платформа для онлайн-обучения дизайну, построенная как **личное рабочее пространство дизайнера**, а не типичный LMS. Тёмная редакционная эстетика уровня Linear / Raycast / Read.cv. Два режима: **студент** (9 экранов) и **наставник** (3 экрана). Всё реализовано как одно приложение с левым сайдбаром и переключением экранов.

## About the Design Files
Файлы в этом пакете — это **дизайн-референсы, созданные в HTML** (прототипы, показывающие желаемый вид и поведение), а **не продакшн-код для копирования**. Задача — **воссоздать эти экраны в целевом кодовом окружении** (React, Vue, Svelte, SwiftUI и т.д.), используя его устоявшиеся паттерны, компоненты и библиотеки. Если окружения ещё нет — выбрать подходящий фреймворк (рекомендация: **React + TypeScript**, CSS-переменные или Tailwind с кастомным конфигом) и реализовать дизайн там.

`Platform.dc.html` — это «Design Component»: разметка обёрнута в рантайм (`support.js`), который рендерит шаблон с `{{ }}`-плейсхолдерами и логику из класса `Component`. **Не тащите рантайм в продакшн** — читайте файл как источник правды по разметке, стилям (все инлайн), копирайту и данным, и переписывайте на нормальные компоненты.

### Как читать исходник
- Вся вёрстка между `<x-dc>…</x-dc>`, стили — **инлайн** (`style="…"`), плюс небольшой `<helmet><style>` с `@font-face`/`@keyframes`/медиа-запросами.
- Экраны — это блоки `<sc-if value="{{ show.<screen> }}">` с атрибутом `data-screen-label="…"`.
- Списки — `<sc-for list="{{ … }}" as="item">`. Данные этих списков лежат в JS-классе `Component` (массивы `modulesRaw`, `comments`, `materials`, `checklist`, `criteria`, `reviewComments`, `gradeRows`, `chatMessages`, `portfolio`, `students`, `queueItems`, `m3lessons`).
- Производные значения (цвета статусов, ширины прогресс-баров) считаются в `renderVals()`.

## Fidelity
**High-fidelity (hifi).** Финальные цвета, типографика, отступы, состояния и микроанимации. Воссоздавать **пиксель-в-пиксель**, подставив реальные данные/аватары вместо плейсхолдеров.

### Типографика
Три семейства (Google Fonts):
- **Lora** (serif) — заголовки, крупные числа, цитаты. Weight 400–600, часто `font-style:italic` для акцентных слов. `letter-spacing:-0.01…-0.02em`.
- **Onest** (sans-serif) — весь UI-текст, кнопки, параграфы. Weight 300–700.
- **JetBrains Mono** (monospace) — лейблы-надзаголовки (КАПСОМ, `letter-spacing:0.06em`), мета, бейджи типов файлов (FIG/PDF/URL), номера, тайм-коды.

Импорт:
```
https://fonts.googleapis.com/css2?family=Onest:wght@300;400;500;600;700&family=Lora:ital,wght@0,400;0,500;0,600;1,400;1,500&family=JetBrains+Mono:wght@400;500&display=swap
```

Шкала (px), наблюдаемая в макетах:
- Hero H1: **64** (Lora 500, line-height 1.04)
- Заголовок экрана H1: **38–46** (Lora 500)
- H2 в контенте: **22–25** (Lora 500)
- Крупное число (KPI): **40–76** (Lora)
- Заголовок карточки: **19–23** (Lora)
- Body урока: **16.5** (Onest, line-height 1.75)
- Body обычный: **13.5–15** (line-height 1.5–1.65)
- UI-текст / кнопки: **13–14.5** (Onest 500–600)
- Мета / подписи: **11–12.5**
- Mono-лейблы: **10–11.5**, `letter-spacing:0.06em`, `text-transform:uppercase`

### Радиусы
Намеренно **разные** (бриф запрещает одинаковые скругления):
- Крупные карточки: `16–18px`
- Средние карточки/панели: `13–15px`
- Кнопки: `9–12px`, пилюли-бейджи: `100px`
- Мелкие иконки-плашки (типы файлов): `5–8px`
- Аватары: `50%`

### Тени
Используются скупо, только на «плавающих» элементах онбординга:
- `0 30px 80px rgba(0,0,0,0.5)`, `0 20px 50px rgba(0,0,0,0.45)`, hover-подъём `0 14px 40px rgba(0,0,0,0.5)`.
- Карточки в приложении теней **не имеют** — разделяются границами и фоном.

### Spacing
Базовый ритм 4px. Типичные значения: gap карточек `18px`, паддинг карточек `20–32px`, паддинг экранов `40–46px 56px`, gap двухколоночных раскладок `36–48px`. Очень много воздуха — не ужимать.

### Анимации
- `fadeIn` (opacity 0→1, .4s ease) — вход каждого экрана.
- `fadeUp` (translateY(14px)+opacity, .7s cubic-bezier(.2,.7,.2,1)) — hero онбординга.
- Hover-микроинтеракции: `transform:translateY(-2…-3px)` на карточках/кнопках, смена цвета границы/фона, `transition` .15–.25s. Play-кнопка плеера: `scale(1.07)` на hover.

## Layout / App Shell
- Корень: `display:flex; height:100vh; overflow:hidden`. Слева сайдбар, справа `<main>` со скроллом (`overflow-y:auto`).
- **Сайдбар** (ширина `256px`, скрыт на экране онбординга): шапка-воркспейс (логотип-плашка с серифной «U» + название «UI/UX Design / Поток 7 · закрытый клуб»), фейковый поиск с `⌘K`, основная навигация, секция «НАСТАВНИК», и внизу карточка профиля студента. Активный пункт: фон `rgba(255,255,255,0.06)`, текст `#F4F2EE` и **акцентная вертикальная риска** слева (2.5px, цвет акцента). Неактивный: текст `rgba(244,242,238,0.46)`.
- Иконки в сайдбаре — простые 16px SVG-примитивы (см. метод `icon()` в классе: grid, list, play, task, check, chat, grid2, user, diamond), `stroke:currentColor; stroke-width:1.4`.
- **Адаптив**: медиа-запросы в `<helmet>` — класс `.split` стекается в колонку на `≤1140px`, bento-сетка `.grid-bento` в одну колонку на `≤900px`.

## Interactions & Behavior
- **Навигация**: единственный источник состояния — `state.screen` (строка). Клик по пункту сайдбара / CTA вызывает `this.setState({screen:id})`. Список экранов: `onboarding, dashboard, course, lesson, homework, review, chat, portfolio, profile, admin, queue, builder`. На онбординге сайдбар скрыт (`showSidebar = screen!=='onboarding'`).
- **Hover-состояния** заданы через `style-hover` почти на всех интерактивных элементах (карточки поднимаются, кнопки светлеют/темнеют, строки таблицы подсвечиваются). Переносить в `:hover` CSS.
- **Анимация входа экрана**: `fadeIn .4s`. Hero — `fadeUp`/`fadeIn`.
- Сабмиты форм, реальная загрузка файлов, видеоплеер, реальный чат — **в прототипе не реализованы** (статичные hi-fi состояния). При разработке навесить реальную логику.

## State Management
Минимальный: один enum-стейт текущего экрана. В реальном приложении заменить на роутер (например `/dashboard`, `/course`, `/lesson/:id`, `/mentor/queue` и т.д.). Данные списков (модули, студенты, очередь, сообщения) — захардкожены в классе как моки; заменить на фетч с бэкенда. Производные UI-значения (цвет статуса, ширина бара, % ) считать на клиенте из данных, как сделано в `renderVals()`.

## Assets
- **Изображения** (превью уроков, кейсы портфолио, аватары) — сейчас **полосатые SVG/CSS-плейсхолдеры** с mono-подписями. Заменить на реальные медиа.
- **Аватары** — CSS-паттерн `repeating-linear-gradient` + инициалы. Заменить на фото.
- **Иконки** — инлайн-SVG-примитивы 16px (метод `icon()`), `stroke:currentColor`. Можно заменить на любую stroke-иконку-библиотеку (Lucide и т.п.) аналогичного веса (~1.4–1.5 stroke).
- **Шрифты** — Google Fonts (Onest, Lora, JetBrains Mono).
- Эмодзи/декоративных глифов нет (кроме функциональных стрелок/символов ▸ ↥ ⠿ ✓).

- `01-onboarding.png`, `02-dashboard.png`, `03-course-roadmap.png`, `04-lesson.png`, `05-homework.png`, `06-review.png`, `07-chat.png`, `08-portfolio.png`, `09-profile.png`
- `10-mentor-overview.png`, `11-mentor-queue.png`, `12-mentor-builder.png`

## Files
- `Platform.dc.html` — все 12 экранов, шаблон (инлайн-стили) + класс `Component` с данными и логикой. **Главный источник правды.**
- `support.js` — рантайм Design Component (для просмотра прототипа; в продакшн не нужен).
- `screens/*.png` — скриншоты экранов.

Чтобы посмотреть прототип: открыть `Platform.dc.html` в браузере. Стартует с онбординга, «Начать обучение» вводит в приложение, дальше переключение через сайдбар.
